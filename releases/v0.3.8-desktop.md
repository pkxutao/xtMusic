# XT Music v0.3.8 · 全曲库随机播放

本版本面向 Windows x64 与 Ubuntu amd64，延续此前发布的 0.3.7 桌面客户端（src/ Electron 实现）。不修改原生 Rust 分支目录 native/ 或安卓端，也不覆盖已有安装包。

## 使用方法

打开「歌曲 / 所有歌曲」，点击 **全部随机播放**。首次会分页扫描当前账号的整个曲库，只读取歌曲信息，不下载音频或全部封面。准备期间可取消，当前播放不受影响；完整扫描结束后才替换播放队列。

歌曲页面仍按每页最多 400 首显示，上下均提供分页入口。**显示范围与播放范围完全独立**，播放来源区域和播放队列会显示完整歌曲数量。

收藏、歌单、专辑和风格页的「全部随机播放」使用各自的全部歌曲；「最近播放」仍明确为本页随机。底部随机按钮只切换当前播放来源的顺序，不会擅自扩大播放范围。

## 随机与恢复

- Fisher–Yates 洗牌，一轮内自动播放不重复。手动回听、跳转和单曲循环不计入此限制。
- 上一首/下一首可沿实际历史回听。播放超过 4 秒时，上一首先回到当前歌曲开头。
- 关闭列表循环时，播完本轮停止；开启列表循环后重新洗牌，至少两首歌时避免两轮交界立即重复。
- 大队列使用 IndexedDB 异步保存，不再受原 500 首快照限制；歌曲信息与播放顺序分开保存。
- 按服务器和用户名隔离索引与队列；切换账号或重新登录同一账号可恢复。删除账号会删除该账号的播放记录。
- 重启不自动出声；点击播放恢复当前曲目，正常暂停/拖动时保存进度，连续播放每 15 秒记录一次进度。
- 原 0.3.7 的无账号标识临时队列不会自动迁移，避免恢复到其他账号；登录配置不受影响。

## 曲库一致性与错误处理

完整索引可在五分钟内复用，复用前校验服务器总数和首批标识；「重新扫描并随机播放」强制刷新。曲库扫描期间新增/删除导致总数变化、重复分页、提前空页或网络失败时，不会将不完整曲库标成全部，也不会覆盖原队列。

未返回总数的服务会持续分页至空页，列表保留下一页入口；遇到小于 400 的服务端分页上限会适配。索引不是音频离线缓存，播放仍需连接 NAS。歌曲删除或暂不可播放时保留错误提示，可切换下一首。

## 安装包

- `XT-Music-0.3.8-ubuntu-amd64.deb`：Ubuntu 安装包
- `XT-Music-0.3.8-ubuntu-x86_64.AppImage`：Linux 便携包
- `XT-Music-0.3.8-x64.exe`：Windows 安装程序
- `XT-Music-Portable-0.3.8-x64.exe`：Windows 便携包

Ubuntu 安装：`sudo apt install ./XT-Music-0.3.8-ubuntu-amd64.deb`。正常退出旧客户端后升级，不需要删除原登录配置。仅 x86-64/amd64，不是 ARM64；未配置 Windows Authenticode 生产签名。

## 验证边界

自动化验证使用本地模拟飞牛服务与实际应用主进程、IPC、预加载桥、音频代理、IndexedDB；覆盖 12,345 首完整索引、翻页保持队列、随机历史、完整进程重启、进度恢复、账号切换、取消/失败保护、缺失总数和 200 首分页上限。单元测试包含 100,001 首曲库和完整随机轮次；保留已有大曲库、歌词、专辑跳转和字体回归。

CI 构建/安装的实际结果以随包 `BUILD-INFO-*`、`VERIFICATION-*` 与测试截图为准。没有使用用户真实飞牛账号，未验收真实 NAS 版本兼容性、物理声卡、蓝牙、Wayland 或 FUSE 挂载 AppImage。测试通过不代表已完成这些实机验证。
